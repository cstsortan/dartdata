# Specification: Schema Migration

**Track ID:** schema-migration_20260405
**Type:** Feature
**Created:** 2026-04-05
**Status:** Draft

## Summary

Implement all three `MigrationPolicy` modes (`automatic`, `none`, `resetOnConflict`) so that `ModelContainer` can detect schema drift on open and respond accordingly — adding columns, throwing errors, or resetting the database.

## Context

`ModelContainer` already creates a `_schema_version` table on first open, but the value is never compared on subsequent opens. The `MigrationPolicy` enum exists but is ignored. The existing test suite has one test that simulates column-adding migration manually — this track makes it automatic.

## User Story

As a developer iterating on my data model, I want the library to automatically add new columns when I add fields to my `@model` classes, so that I don't have to write migration SQL by hand during development.

## Acceptance Criteria

- [ ] `MigrationPolicy.automatic`: new columns are added via `ALTER TABLE ADD COLUMN`; new tables are created; existing data is preserved
- [ ] `MigrationPolicy.automatic`: removed columns are ignored (not dropped) — additive only
- [ ] `MigrationPolicy.none`: throws `SchemaMismatchError` if any table/column differs from the schema
- [ ] `MigrationPolicy.resetOnConflict`: drops all model tables and recreates them from scratch
- [ ] Schema fingerprint is stored and compared on each open
- [ ] All existing tests continue to pass (they use in-memory DBs which always start fresh)
- [ ] New tests cover each policy mode

## Dependencies

- Existing: `MigrationPolicy` enum, `_schema_version` table, `SchemaMismatchError`
- Existing: `ModelContainer._applySchema()` and `_createTableIfNeeded()`

## Out of Scope

- Column renames or type changes (require manual `MigrationPlan`)
- Custom migration steps/callbacks (`MigrationPolicy.custom`)
- Data migration (transforming existing row values)

## Technical Notes

- Schema fingerprint: hash the sorted list of `(tableName, columnName, columnType, constraints)` tuples
- On open: read `_schema_version.fingerprint`, compare to current schema hash
- `automatic`: use `PRAGMA table_info(tableName)` to find existing columns, `ALTER TABLE ADD COLUMN` for missing ones
- `resetOnConflict`: `DROP TABLE IF EXISTS` for each model table, then recreate
- `none`: throw `SchemaMismatchError` with details of what changed
- SQLite limitation: `ALTER TABLE` cannot add columns with PRIMARY KEY or UNIQUE constraints — handle gracefully
