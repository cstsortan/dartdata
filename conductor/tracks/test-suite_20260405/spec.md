## Summary

Create a comprehensive test suite for the dartdata library covering unit and integration tests, validating that the implemented API matches the API_DESIGN.md specification and that all key design decisions hold.

## Context

dartdata is a Flutter persistence library inspired by SwiftData. The library has annotated models, type-safe queries, ModelContainer/ModelContext CRUD operations, ExternalFile blob storage, and a code generator. The CLAUDE.md documents several critical design decisions (SQLite internals with `z_pk`/`z_opt`, WAL mode, FK enforcement, ExternalFile sealed state machine). This suite serves as a living validation layer ensuring the implementation matches both the intended API and the design decisions.

## User Story

As a developer of the library, I want to run a full test suite to validate that it works as expected, and that the API actually matches the API_DESIGN.

## Acceptance Criteria

- [ ] All key design decisions from CLAUDE.md are covered by tests (z_pk/z_opt columns, WAL mode, FK enforcement, ExternalFile states, flat `_EXTERNAL_DATA/` layout)
- [ ] All major API surface areas from API_DESIGN.md are covered (ModelContainer, ModelContext, Query/Predicate/Sort, @relationship DeleteRules, ExternalFile lifecycle)
- [ ] Unit tests validate individual components in isolation (QueryField operators, Predicate composition, ExternalFile state transitions, Schema/ColumnDefinition)
- [ ] Integration tests validate end-to-end flows using an in-memory SQLite database (insert/fetch/update/delete, transactions, rollback, changes stream)
- [ ] All tests run from `dartdata/` with `flutter test` and pass with zero failures
