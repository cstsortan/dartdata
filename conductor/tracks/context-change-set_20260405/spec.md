# Specification: Full ContextChangeSet

**Track ID:** context-change-set_20260405
**Type:** Feature
**Created:** 2026-04-05
**Status:** Draft

## Summary

Replace the stub `ContextChangeSet` (currently empty) with a fully populated change set that tracks which tables had inserts, updates, and deletes during each `save()` call. Also populate the `_change_log` table for persistent history.

## Context

`ModelContext.save()` currently emits an empty `ContextChangeSet()` on the `changes` stream. The `_change_log` table exists in every database but is never written to. `QueryObserver` (Track H) will depend on knowing which tables changed to decide whether to re-run queries.

## User Story

As a developer building reactive UI, I want the `changes` stream to tell me exactly which tables were modified and what type of changes occurred, so that my `QueryObserver` widgets only rebuild when their data actually changes.

## Acceptance Criteria

- [ ] `ContextChangeSet` contains per-table change records: `{tableName: {inserts: [...], updates: [...], deletes: [...]}}`
- [ ] Each change record includes the model type and primary key
- [ ] The `changes` stream emits a populated `ContextChangeSet` after every successful `save()`
- [ ] `_change_log` table is populated with `(entity, entity_pk, change_type, timestamp)` rows
- [ ] Empty save (no pending ops) does not emit on the stream
- [ ] Existing tests continue to pass (they only check that an event is emitted, not its contents)

## Dependencies

- Existing: `ContextChangeSet` class (stub), `_ChangeNotifier`, `changes` stream
- Existing: `_change_log` table schema in `ModelContainer`
- Blocks: Track H (`QueryObserver`) depends on populated change sets

## Out of Scope

- Per-field change tracking (only per-row)
- Change set diffing (before/after values)
- Cross-context change notification (multiple `ModelContext` instances)

## Technical Notes

- During `_processInserts()`, `_processUpdates()`, `_processDeletes()`: collect `(tableName, id, changeType)` tuples
- After successful transaction commit, wrap tuples into `ContextChangeSet` and emit
- Change types: `insert`, `update`, `delete` (enum)
- `_change_log` table: `INSERT INTO _change_log (entity, entity_pk, change_type, timestamp) VALUES (?, ?, ?, ?)`
- Timestamp: milliseconds since epoch (consistent with DateTime encoding)
