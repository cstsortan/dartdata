# Specification: Generator — ExternalFile Field Handling

**Track ID:** generator-external-files_20260405
**Type:** Feature
**Created:** 2026-04-05
**Status:** Draft

## Summary

Extend the code generator to detect `ExternalFile` and `ExternalFile?` field types and emit the correct column definition (`TEXT` for UUID storage), serialization code in `toMap()`/`fromMap()`, and registration in the descriptor's `externalFileFields` list.

## Context

The generator already detects `ExternalFile` field types (noted in the exploration) but does not fully emit the serialization logic. The hand-written test models (`test_models.dart`) demonstrate the expected `toMap` (extract managed path) and `fromMap` (reconstruct via `ExternalFile.fromManagedPath`) patterns. The runtime `ModelContext` already handles `ExternalFile` persistence correctly — the generator just needs to produce the right glue code.

## User Story

As a developer, I want to declare `ExternalFile? imageData` on my model and have the generator automatically handle serialization so that blob files are stored and retrieved without hand-written code.

## Acceptance Criteria

- [ ] `ExternalFile` / `ExternalFile?` fields produce a `TEXT` column in `ColumnDefinition` (stores UUID string)
- [ ] `toMap()` emits: extract the UUID filename from managed state, or null if not managed
- [ ] `fromMap()` emits: reconstruct `ExternalFile.fromManagedPath(row['fieldName'])` when non-null, or null
- [ ] Field is registered in `externalFileFields` list on the generated descriptor
- [ ] `ExternalFile` fields are NOT included as `QueryField` statics (can't query blob content)
- [ ] Nullable `ExternalFile?` correctly handles null in both directions

## Dependencies

- Existing: `ExternalFile` sealed state machine (fully implemented)
- Existing: `ModelContext._persistExternalFiles()` and `_deleteExternalFiles()`
- Existing: hand-written test model demonstrates expected output format

## Out of Scope

- Changing the `ExternalFile` class itself
- Eager loading of external files on fetch
- Blob compression or encryption

## Technical Notes

- In `toMap()`: for `ExternalFile` fields, check if managed and extract the UUID filename; emit null otherwise
- In `fromMap()`: check `row['fieldName'] != null`, then construct `ExternalFile.fromManagedPath(blobDir + '/' + row['fieldName'])`
- The `ModelContext` handles the actual I/O (persist/delete) — the generated code only handles serialization
- `externalFileFields` is used by `ModelContext` to know which fields need file I/O during `save()`
