# Specification: Blob Maintenance (cleanOrphanedBlobs)

**Track ID:** blob-maintenance_20260405
**Type:** Feature
**Created:** 2026-04-05
**Status:** Draft

## Summary

Implement `ModelContainer.cleanOrphanedBlobs()` to scan the `_EXTERNAL_DATA/` directory, cross-reference blob UUIDs against all `ExternalFile` columns in the database, and remove files that no longer have a corresponding row.

## Context

`cleanOrphanedBlobs()` exists as a stub that returns 0. Orphaned blobs can occur when: a crash interrupts `save()` after writing the file but before committing the SQLite transaction; or when a bug in delete logic misses a blob file. This utility is a safety net for production reliability.

## User Story

As a developer, I want a maintenance utility that cleans up orphaned blob files, so that disk space isn't wasted by files that are no longer referenced by any model.

## Acceptance Criteria

- [ ] `cleanOrphanedBlobs()` returns the count of removed files
- [ ] Files in `_EXTERNAL_DATA/` with no matching UUID in any ExternalFile column are deleted
- [ ] Files that ARE referenced are not deleted
- [ ] Works with multiple model types that have ExternalFile fields
- [ ] Safe to call during normal operation (does not interfere with active contexts)

## Dependencies

- Existing: `_EXTERNAL_DATA/` directory layout
- Existing: `ExternalFile` column stores UUID string
- Existing: stub method in `ModelContainer`

## Out of Scope

- Automatic cleanup on startup (user calls it manually)
- Scheduled cleanup / background processing
- Blob compression

## Technical Notes

- Scan `_EXTERNAL_DATA/` directory for all file names (UUIDs)
- For each model descriptor with `externalFileFields`, query `SELECT DISTINCT <field> FROM <table> WHERE <field> IS NOT NULL`
- Collect all referenced UUIDs into a Set
- Delete any file whose name is NOT in the set
- Return count of deleted files
