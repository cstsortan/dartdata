# Specification: Relationship Enforcement & Delete Rules

**Track ID:** relationship-enforcement_20260405
**Type:** Feature
**Created:** 2026-04-05
**Status:** Draft

## Summary

Implement runtime enforcement of relationship delete rules (cascade, nullify, deny) in `ModelContext.save()` and add the ability to fetch related objects through declared relationships.

## Context

The `@relationship` annotation and `DeleteRule` enum are fully declared, and `ModelContainer` creates FK columns correctly. However, `ModelContext` does not enforce delete rules during `save()`, and there is no API to traverse relationships (e.g., `trip.bucketList`). Three tests in `relationship_test.dart` are currently skipped awaiting this implementation.

## User Story

As a developer using dartdata, I want delete rules (cascade, nullify, deny) to be automatically enforced when I delete a model, so that referential integrity is maintained without manual bookkeeping.

## Acceptance Criteria

- [ ] `DeleteRule.cascade`: deleting a parent cascades to delete all children
- [ ] `DeleteRule.nullify`: deleting a parent sets child FK columns to NULL
- [ ] `DeleteRule.deny`: deleting a parent throws `StateError` if children exist
- [ ] `DeleteRule.noAction`: deleting a parent leaves children as orphans
- [ ] Related objects can be fetched via relationship descriptors (lazy loading)
- [ ] All 3 skipped relationship tests pass
- [ ] New tests cover each delete rule and relationship traversal
- [ ] `flutter test` passes with zero failures

## Dependencies

- Existing: `@relationship` annotation, `DeleteRule` enum, `RelationshipDefinition`, FK column creation in `ModelContainer`
- Existing: `relationship_test.dart` with 3 skipped tests

## Out of Scope

- Many-to-many junction table creation (that's the generator's job — Track E)
- Eager loading / batch prefetch optimization
- Inverse relationship auto-wiring at runtime

## Technical Notes

- Delete rules should be enforced in `ModelContext._processDeletes()` (or equivalent) before the SQL DELETE
- Use `RelationshipDefinition` metadata from the descriptor to find child tables and FK columns
- For cascade: recursively delete children (depth-first to respect nested cascades)
- For nullify: UPDATE child rows SET fk_col = NULL before deleting parent
- For deny: SELECT COUNT(*) from child table WHERE fk_col = parent.z_pk; throw if > 0
- Relationship fetching: add a `fetchRelated<T>()` method or extend descriptors with accessor helpers
- The z_pk integer (not user id) is what FK columns reference
