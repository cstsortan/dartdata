# Specification: Generator — @attribute Annotation Reading

**Track ID:** generator-attributes_20260405
**Type:** Feature
**Created:** 2026-04-05
**Status:** Draft

## Summary

Complete the code generator's handling of `@attribute` annotations so that `primaryKey`, `unique`, `indexed`, `columnName`, and `transient` parameters are read and reflected in the generated `ModelDescriptor` and serialization code.

## Context

The generator (`dartdata_generator/lib/src/model_generator.dart`) currently ignores `@attribute` parameters — it infers nullability from the type but does not read `primaryKey`, `unique`, `indexed`, `columnName`, or `transient`. There is a TODO at line ~124 marking this gap. The hand-written test models (`test_models.dart`) manually set these flags, proving the runtime supports them — the generator just needs to emit them.

## User Story

As a developer, I want to annotate my model fields with `@attribute(primaryKey: true)` or `@attribute(indexed: true)` and have the code generator automatically produce the correct `ColumnDefinition` with those constraints, so I don't have to write descriptors by hand.

## Acceptance Criteria

- [ ] `@attribute(primaryKey: true)` sets `isPrimaryKey: true` in the generated `ColumnDefinition`
- [ ] `@attribute(unique: true)` sets `isUnique: true`
- [ ] `@attribute(indexed: true)` sets `isIndexed: true`
- [ ] `@attribute(columnName: 'custom_name')` overrides the default snake_case column name
- [ ] `@attribute(transient: true)` excludes the field from `columns`, `toMap()`, and `fromMap()`
- [ ] Fields without `@attribute` use default inference (current behavior preserved)
- [ ] Generator tests verify correct output for each annotation parameter

## Dependencies

- Existing: `@attribute` class in `annotations/model.dart`
- Existing: `ColumnDefinition` with all flag fields
- Existing: `ModelGenerator` in `dartdata_generator`
- Requires: `source_gen` `ConstantReader` API for reading annotation values

## Out of Scope

- `@relationship` annotation reading (Track E)
- `ExternalFile` field handling (Track F)
- Runtime validation of constraints (that's `ModelContainer`'s job)

## Technical Notes

- Use `ConstantReader` to read the `@attribute` annotation: `element.metadata` → find `attribute` annotation → `read('primaryKey')`, etc.
- A field can have both `@attribute` and no annotation — handle both cases
- `transient` fields should be completely absent from generated SQL and serialization
- `columnName` override should propagate to both the `ColumnDefinition` and the `QueryField` static
- Test approach: create annotated sample models in the generator's test fixtures, run the generator, and assert on the output string
